# 产品价值：把硬件的 AI 能力挖到极致

## 一句话
核心价值是**挖掘特定硬件（如 Jetson Orin Nano）的 AI 能力**——让 GPU/NPU、内存带宽、功耗/散热为模型跑到**该有的性能与稳定性**。发行版只是载体，模型只是负载，"最新模型"只是招牌。

## 核心：硬件能力挖掘（性能工程）

| 层面 | 抓手 | 产出证据 |
| --- | --- | --- |
| **计算** | TensorRT/RKNN 引擎、量化(FP16/INT8)、算子融合、batch | 延迟 / FPS / 精度 |
| **内存** | 带宽利用、显存复用、zero-copy、GPU/DLA 分工 | 内存占用、带宽利用率 |
| **功耗/散热** | DVFS/时钟、风扇策略、功耗-性能曲线 | 功耗、温度、降频 |
| **系统** | 内核/驱动/CUDA 定版、CPU 隔离、实时性 | 稳定性、抖动 |
| **度量** | 上面的数字标准化 | 一张"性能墙 / 对比表" |

> **"硬件为核心"的落点不是"把系统装上去"，而是"把硬件能力挖出来"。** 发行版/系统是实现手段，不是价值本身。

## 三个层次（从核心到外围）

1. **硬件能力挖掘（核心）**：性能工程——把板子的算力/带宽/功耗榨到该有的水平。
2. **可复现交付**：KAS 定版、最小镜像、OTA——让上述优化能稳定复制到每台设备。
3. **快速跟进新模型（钩子）**：证明方法有效、跟得上；有吸引力，但不是核心。

## 构建 / 迭代速度也是价值

- **对客户**：从"改配置/换模型"到"设备上更新完"的时间越短，上线越快、成本越低。
- **对自己**：迭代快 = 试错便宜 = 能快速跟进新模型/新硬件（这正好支撑"最新模型快速上线"的钩子）。
- **手段**：KAS 锁版本 + DL/sstate 缓存（含 CI 复用）+ 精简镜像（无 GUI/AI 包）+ 分层目标（**lean 迭代 / full 发布**）。
- **证据**：首次构建时间、**增量构建时间**、CI 单次构建时间、CI 是否复用缓存。

> 慢的根因要能解释：本地 7GB 内存换页、sstate 未命中、全量镜像含 CUDA/llama——**把"为什么慢"讲清楚，本身就是专业度**。

## 对客户的价值

| 维度 | 客户得到什么 | 可证明的方式 |
| --- | --- | --- |
| **更高性能** | 同样的板子跑出更高的吞吐/更低的延迟、更好的性能/瓦 | TensorRT 基准、量化前后对比、功耗-性能曲线 |
| **省时间** | 从"模型 + 板子"到"可交付服务"，把数天/数周底层集成与调优压缩掉 | 一条命令从零到运行（quickstart） |
| **降风险** | 稳定（长时间不倒）、可复现（换机器一致）、可更新（OTA 不砖） | soak test、KAS 锁版本、A/B 升级 |
| **省钱** | 最小镜像 + 更便宜板子 + 更低功耗 | 镜像大小、功耗、BOM 对比 |

## 市场空位（详见 `13-landscape.md`）

- **开发体验**有人做了：`jetson-containers`（~4.9k★）、`jetson-inference`（~9k★）。
- **BSP**有人做了：`meta-tegra`（~580★）、`tegra-demo-distro`。
- **通用边缘 OS / OTA**有人做了：Balena、Torizon、Foundries；`Mender`、`RAUC`。
- **缺的是**：开源、最小、可复现、**面向生产上板**、带**稳定/性能数据**的发行版。

> 开发体验别人做了，**生产交付（更小、更稳、可复现、可更新、有数据）没人做**。

## 不可替代的部分（人）

- 软件从 **BSP 到 UI 全栈**都懂（少见的组合）；
- 有**真实在维护的仓库**（`embedai`）作为活证据；
- 多年系统经验 = 出问题时能**兜底**。

## 不是价值的（是手段）

发行版本体、Yocto/BitBake 管道、支持多少块板子——这些是**实现手段**，不是卖点。

## 必须测出来、对外证明的数字

> 没有这些数字，价值只是口号。每个都要有"测量方法 + 脚本 + 可复现"。

**核心（硬件能力挖掘的直接证据）**
1. **推理性能**：延迟 / FPS（TensorRT，同一模型量化 FP16 / INT8 前后对比）。
2. **性能/瓦**：FPS per Watt（功耗-性能曲线）——最能体现"把硬件挖到极致"。
3. **资源利用率**：GPU/NPU 利用率、内存带宽利用率。
4. **精度**：量化前后的模型精度（别只看速度）。

**交付（可复现与效率）**
5. **尺寸与启动**：镜像大小（vs JetPack / jetson-containers）+ 启动时间。
6. **稳定性**：soak test 连续运行小时数（无崩溃、无异常降频）。

> 这 6 个数字 = 你的"性能墙"，既是最有说服力的内容，也是最有力的销售材料。

## "把最新模型快速上线"算不算价值？

**算，但它是"钩子 / 能力"，不是"护城河"。**

- **"最新"是证据**：证明你的方法有效、跟得上（如"某新模型发布后 N 天内在 Orin Nano 上跑起来"）。
- **护城河是系统化能力**：量化/编译（TensorRT / RKNN / ONNX Runtime）、硬件栈定版、稳定/性能基准、OTA、可复现。
- **只有"能跑 demo"会被超越**；"能稳定、可复现、可更新地交付"才是壁垒。追最新模型如果没有可复用的流水线，会陷入"永远在打样"。
- **服务化**：把"新模型 X → 你的板子 → 可用服务"做成**可计时**的交付（例如 N 天/N 周），这是可以直接卖的。
- **内容化**："最新模型上 Jetson" 是强选题，但每期必须落到"**我怎么做到 + 数据**"，而不是"我也跑了个 demo"。

> 一句话：**"最新"负责吸引注意，"可复现 + 稳定 + 数据"负责留住信任。**

## 如何用这些价值拿流量与好评

- **对比实测**是最强钩子：同一模型在 embedai vs JetPack vs jetson-containers 上的 5 个数字。
- **诚实标注限制**（QEMU 无 GPU、目前只支持 Jetson）→ 反而增加可信度。
- 数据 → 文章 → 视频 → GitHub star / Release 下载 → 客户线索。
